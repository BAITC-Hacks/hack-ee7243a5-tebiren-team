# Career Quest

Локальное демо HackAlem AI: профиль сотрудника → карьерная цель → объяснимые шаги развития → выполнение → обновление навыков. HR видит пробелы, участие по активностям и сотрудников без подходящего шага.

React + TypeScript + Vite; FastAPI + Python; SQLite. Исходный синтетический набор: 200 сотрудников, 40 активностей, 60 навыков, 2743 записи истории. Дата снимка: **2026-10-01**.

## Быстрый запуск — Windows / PowerShell

Требуются Node.js 22.12+ и Python 3.11+. Все команды выполняются **из корня этого репозитория**, где находится package.json, а не из папки backend.

Первоначальная установка:

```powershell
npm ci
py -3 -m venv backend/.venv
& .\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm run setup:demo
```

Последняя команда спрашивает ID сотрудника (Enter → E0002) и два пароля не короче 12 символов, с подтверждением. Логины: `hr` и `employee`. Пароли вводятся без отображения, сохраняются только солёные хеши. Общего пароля в репозитории нет. Повторный запуск настройки просит подтверждение замены паролей и отзывает сессии.

Запуск обоих компонентов одной командой:

```powershell
npm run dev
```

Открыть [Career Quest](http://127.0.0.1:5173). Backend: [health](http://127.0.0.1:8000/api/health), [OpenAPI](http://127.0.0.1:8000/docs). `Ctrl+C` останавливает процессы, созданные этой командой. Не используйте несколько backend-процессов/workers с одной БД.

Если 8000 или 5173 занят, остановите **свой прежний сервер** в его терминале через Ctrl+C. Запуск не убивает посторонние процессы и не выбирает другой порт молча. Либо задайте свободные порты в текущем PowerShell:

```powershell
$env:CQ_FRONTEND_PORT="5179"
$env:CQ_BACKEND_PORT="8010"
npm run dev
```

Frontend использует same-origin `/api` proxy: сессии работают без отключения браузерных защит. Старый фронтенд и новый backend (или наоборот) несовместимы после добавления входа — перезапускайте оба.

## Настройка OpenAI

Без ключа приложение полностью работает на реальном backend, с алгоритмическими рекомендациями. Это **не mock-режим**.

Создайте локальный `backend/.env` по `backend/.env.example`, не перезаписывая уже имеющийся файл. Укажите:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
```

Альтернативно, если ключ уже сохранён в отдельном приватном текстовом файле, удалите строку `OPENAI_API_KEY` и используйте:

```dotenv
OPENAI_API_KEY_FILE=API key.txt
OPENAI_MODEL=gpt-4o-mini
```

Относительный путь считается от backend. Файл содержит только ключ, без кавычек и префиксов. `backend/API key.txt` и `.env` исключены из Git; файлы ключей с другими именами исключайте самостоятельно. Ключ не копируется во frontend. Переменные текущего процесса имеют приоритет над .env; явно пустой `OPENAI_API_KEY` выключает AI даже при заданном файле.

Backend сам читает `backend/.env`. После изменения конфигурации перезапустите сервер. Никогда не используйте `VITE_...` для секретов.

`openai_enabled=true` в health означает наличие конфигурации, а не проверенный доступ к модели. Для отдельной **платной** live-проверки:

```powershell
npm run check:openai
```

Она запрашивает три объяснения для синтетического профиля без ФИО, проверяет источник `openai`, неизменность ранжирования/цифр и время ответа. Секреты и полный ответ модели не печатаются.

### Что именно делает AI

1. Python определяет цель, рассчитывает навыки и проверяет допустимость активностей: текущую роль/грейд, prerequisites, будущие сессии, историю и повторяемость.
2. Алгоритм ранжирует допустимые шаги по покрытию разрывов, критичным навыкам, похожей истории, приросту и широте эффекта (веса 0.45/0.25/0.15/0.10/0.05).
3. Backend формирует четыре проверяемые категории оснований: текущий грейд, требования цели, разрывы/прогноз, история. Похожая история — активность того же типа **или** формата; отсутствие такой истории явно указано.
4. OpenAI выбирает порядок 3–4 фактов и смысловой акцент дополнительного объяснения. Возвращает структурированный план из разрешённых ID фактов; текст собирается из проверенных фактов. **Это ограниченное объяснение, а не свободное AI-ранжирование или генерация новых курсов.**
5. Неизвестные/повторные ID, неподтверждённый акцент, ошибки ключа/квоты/сети и таймаут приводят к детерминированному объяснению. Обязательные основания остаются неизменными.

Таймаут SDK — 6 секунд без повторных попыток; общий бюджет ожидания объяснения — 7 секунд, максимум 4 одновременных обращения. При занятых слотах fallback немедленный. Проверенные замеры и границы проверки — в [отчёте](docs/CORE_ACCEPTANCE.md).

## Правила прогресса

Прирост в истории, прогнозе и выполнении использует одно правило:

```text
after = max(before, min(5, activity.max_level, before + activity.gain))
```

Потолок активности ограничивает прирост, но не снижает уже достигнутый уровень. Завершения до/в дату оценки считаются уже включёнными в оценку; отдельно отмеченные симуляции выполнения после снимка учитываются и в день оценки. Порядок симуляций одного дня сохраняется, UUID не определяет порядок начисления.

Готовность — среднее `min(current / required, 1)` по требованиям цели: вес критичного навыка 1.5, остальных 1; итог 0–100%, один знак после запятой. Готовность не гарантирует повышение и не меняет текущий грейд.

Цель берётся из career_goal, иначе — следующий грейд текущей роли. Lead без цели не получает выдуманного повышения. Причины отсутствия шага: `no_target`, `target_met`, `no_eligible_activity`. Обязательные HR-активности не попадают в персональные рекомендации. По данным каталога повторяемая активность — EV_036; остальные нельзя завершить повторно. Все расчёты используют дату снимка, не часы компьютера.

## Вход и доступ

| Действие | Сотрудник | HR |
|---|---|---|
| Профиль, история, рекомендации, выполнение | Только свой ID | Любой профиль демо |
| Общий поиск сотрудников, HR-отчёт | Нет | Да |
| Импорт и сброс демо | Нет | Да |

Роль и employee_id назначает сервер. Без сессии API отвечает 401, при недостаточных правах 403. Cookie HttpOnly/SameSite=Lax, сессия 8 часов, изменяющие запросы требуют CSRF-токен. CORS ограничен доверенными origin. Вход ограничивает повторные неуспешные попытки; logout отзывает сессию.

Для HTTPS выставляйте `CQ_SECURE_COOKIES=true`. По умолчанию серверы слушают только 127.0.0.1. Это локальная демо-авторизация, **не** production SSO/RBAC. Нельзя публиковать её в интернете как готовую кадровую систему.

## Импорт жюри

В HR откройте Import data и выберите один или оба файла:

- employees.json: документ `{"meta": {...}, "employees": [...]}` из стартового набора либо массив сотрудников.
- activity_history.csv: точные столбцы стартового набора (порядок не важен). UTF-8 и UTF-8 BOM, до 5 МБ на файл.

Проверяются обязательные поля, типы/диапазоны, даты, роль/грейд/цель, навыки, ссылки и дубликаты ID. Ошибка одной записи отменяет **весь импорт**; существующие ID не перезаписываются. Ошибка содержит файл, номер строки/записи и описание. История позже снимка сохраняется с предупреждением и не участвует в текущих расчётах.

После импорта видны счётчики и кнопки открытия новых профилей. Серверный поиск по ID/имени/роли и постраничная загрузка не ограничивают доступ первыми 200/500 людьми. Импорт истории обновляет открытый профиль и HR.

Примеры: [examples/jury](examples/jury/README.md). Это локальные проверки, не скрытый набор жюри.

## HR-экран

- 10 наиболее распространённых незакрытых навыков цели.
- Пагинированный список всех людей без шага, причина и переход к профилю.
- Все 40 активностей: уникальные участники и записи по статусам completed / in_progress / dropped / no_show / declined / overdue.
- Completion rate = завершённые записи / все записи истории до даты снимка. Уникальные участники считаются отдельно; повторное участие не увеличивает их количество.

HR-сводка не вызывает OpenAI и не показывает публичный рейтинг сотрудников.

## Данные, резервная копия и сброс

Изменения сохраняются в `backend/var/career-quest.sqlite3`: импорт, история, порядок симуляций, ключи идемпотентности, хеши паролей и сессии. Исходные JSON/CSV в backend/data не изменяются. `CQ_DATABASE_PATH` позволяет задать другую БД (предпочтительно абсолютный путь).

Перед Reset demo data остановите приложение, скопируйте SQLite-файл в безопасное место, затем запустите его. Не храните резервную копию с аккаунтами/сессиями в Git. Сброс требует подтверждения в HR-интерфейсе и возвращает исходные 200 профилей/историю; аккаунты сохраняются. Для восстановления остановите приложение и верните резервную копию на исходный путь.

Хранилище рассчитано на **один процесс backend**: блокировки и атомарные транзакции предотвращают двойное начисление в нём. Несколько процессов с одной БД не поддерживаются.

## Команды и проверка

| Команда | Назначение |
|---|---|
| npm run dev | Frontend + реальный backend |
| npm run dev:frontend | Только Vite; backend запускается отдельно |
| npm run dev:backend | Только backend, без auto-reload |
| npm run dev:mock | Явный UI-preview на mockApi, без backend/авторизации |
| npm run setup:demo | Локальные учётные записи |
| npm run test:backend | Изолированные автоматические тесты; без платных AI-вызовов |
| npm run check:openai | Отдельная live-проверка OpenAI |
| npm run build | Проверка TypeScript и production-сборка |
| npm run preview | Просмотр сборки через proxy; backend нужен отдельно |

Frontend-зависимости фиксирует package-lock.json (`npm ci`), Python — backend/requirements.lock, подключённый через requirements.txt. Основные тесты не используют рабочую БД и не сбрасывают пользовательское демо.

## Сценарий защиты

1. Войти как HR, выбрать E0002, показать текущий и целевой грейд, дату и объяснение готовности.
2. Нажать Find my next step; показать факторы и прогноз. Выполнить **действительно возвращённый** шаг, сверить реальные изменения, историю и обновлённый подбор.
3. Импортировать оба файла examples/jury; открыть E9001: критичный System Design, низкий Public Speaking, три пропуска. E9002 показывает переход в другую роль, E9003 — отсутствие цели.
4. Открыть HR overview: участие и переход к человеку без шага.
5. Перезапустить приложение и показать сохранённые изменения.
6. Войти как employee: доступны только свои данные, HR/import скрыты и закрыты на API.
7. При желании показать fallback без OpenAI в отдельном процессе/БД, не уничтожая основное демо.

## Ограничения этапа

Синтетические данные, фиксированная дата, англоязычный desktop-first UI. Нет SSO, промышленных миграций БД, распределённого хранилища, production-деплоя и редактирования карьерной цели через UI. Выполнение — демо-симуляция, не подтверждение посещения курса. Геймификация (награды, валюта, бейджи) — следующий отдельный этап.
