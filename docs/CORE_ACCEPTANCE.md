# Проверка реализации основного ТЗ

Дата: 23 сентября 2026. Проверена рабочая копия после реализации CQ-01…CQ-10. Геймификация не входит в этот этап. Среда: Windows, Node 24.14.1, Python 3.12.14.

## Автоматические проверки

- `npm run test:backend`: **49 passed**, 22.77 секунды. Тесты используют временную SQLite, не рабочую БД и не платный AI.
- `npm run build`: TypeScript + Vite успешно. Основной JS 288.71 КБ, графики выделены отдельно (368.11 КБ); предупреждения о большом едином бандле нет.
- `pip check`: No broken requirements found.
- `git diff --check`: ошибок нет.
- `npm ci --ignore-scripts --no-audit --no-fund`: повторная установка frontend по lock-файлу успешна (142 пакета). Это не проверка установки Python на новой машине.

## Настоящий OpenAI

Отдельный live-запрос к gpt-4o-mini с ключом из локального приватного файла:

- 3 из 3 объяснений имеют `explanation_source=openai`.
- **5.093 секунды** на подбор с обогащением.
- event_id, rank, score, skill_impacts, evidence и reasons совпали с алгоритмическим baseline.
- Ключ, токены и ФИО в вывод теста не попадали.
- Запрос из ограниченного сетевого окружения вернул fallback за 1.062 секунды; после разрешённого сетевого доступа live-проверка прошла.

Роль модели намеренно ограничена: выбор порядка проверенных фактов и акцента, а не произвольный текст с новыми утверждениями. Это уточнение способа реализации CQ-03; свободная генерация и AI-переранжирование не добавлены.

Локальный backend/.env указывает на существующий API key.txt, без копирования ключа в код. Оба файла проверены через git check-ignore и не входят в изменения Git. Health нового процесса подтвердил чтение конфигурации (`openai_enabled=true`); само по себе это не тест успешного обращения — его подтверждает отдельный live-запрос выше.

## Проверки в браузере

Проверены вручную средствами browser automation, не автоматическим frontend test suite:

1. Вход HR, профиль E0002, корректная дата снимка и три рекомендации с основаниями/прогнозом.
2. Выполнение EV_005 из реально возвращённого списка: API Design 1→2, System Design 1→2, готовность 59.3→63.7%; обновились профиль и подбор.
3. Импорт двух файлов examples/jury: 3 профиля и 3 строки истории; кнопка открытия E9001 работает, в истории три no-show, в обосновании подходящего формата — 3 missed.
4. HR: таблица 40 активностей; список без шага, переход к E0006, отдельное состояние no_target.
5. Logout, вход employee: нет HR/import/выбора других людей; прямой переход на /hr возвращает свой профиль. Серверные запреты проверены отдельно тестами.
6. Hot reload клиента не теряет возможность POST: CSRF восстанавливается через текущую сессию.
7. На отдельном fault-стенде рекомендации задержаны на 3 секунды: смена E0002→E0006 не подставляет поздние карточки E0002 в другой профиль.
8. На том же стенде первый GET профиля после успешного complete специально возвращает 503: UI явно сообщает, что выполнение сохранено; старые карточки скрыты. Refresh data восстанавливает экран без повторного начисления. Два намеренных выполнения оставили ровно две runtime-записи с порядком 1,2.
9. Перезапуск backend с той же изолированной SQLite: сессия и фактический прогресс сохраняются.

Fault-стенд — `backend/tests/ui_harness.py`, обычный запуск его **не использует**. Он требует отдельную БД с именем ui-acceptance.sqlite3 и явно отключённый OpenAI. Все импорт/complete/reset проверки выполнялись на изолированных тестовых БД. Рабочий сервер пользователя на 8000 и его данные не сбрасывались.

## Замеры локального API

Один прогретый замер через Vite proxy, без нагрузки:

| Запрос | Время |
|---|---:|
| Профиль E0002 | 52 мс |
| HR summary | 125 мс |
| HR no-next-step list | 113 мс |
| Подбор без OpenAI | 38 мс |
| Подбор + настоящий OpenAI | 5093 мс |

Показатели API не равны времени полной отрисовки страницы. В браузере видны немедленные индикаторы загрузки; точные paint/FCP/p95 и длительный нагрузочный тест не измерялись. Один успешный AI-запрос не гарантирует такую же задержку внешнего провайдера всегда; при задержке действует общий fallback-бюджет.

## Воспроизводимость и границы

Единый `npm run dev` запустил frontend/backend на свободных тестовых портах. При занятом 8000 команда завершилась с понятным сообщением, не завершив чужой процесс. После проверки остановлены только созданные тестовые серверы: порты 5179/5180/8010/8011 освобождены, исходный сервер пользователя на 8000 продолжает отвечать. Настройка Windows, команды, роли, формулы, AI, импорт и резервная копия описаны в корневом README. Зависимости закреплены в lock-файлах.

Не проверены: чистая установка Python-зависимостей на другом компьютере/ОС, скрытые профили жюри, production-нагрузка, SSO и развёртывание в интернете. Их нельзя считать подтверждёнными этой локальной проверкой. База рассчитана на один процесс backend; UI desktop-first. Локальные .env, ключи и БД не переносятся через Git.

Следующий этап — отдельное ТЗ на геймификацию. Награды, валюта и бейджи в текущей реализации не добавлялись.
