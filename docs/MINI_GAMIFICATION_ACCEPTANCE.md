# Проверка мини-геймификации

23 сентября 2026 года. Реализован обязательный минимум из TZ_MINI_GAMIFICATION.md: два значка, фактическая обратная связь и короткая анимация. Необязательные иконки карьерного маршрута не добавлялись.

## Что изменилось

- First step: одна завершённая добровольная активность; Building momentum: три разных активности.
- Счётчик вычисляется сервером из истории до даты снимка. Обязательные мероприятия, другие статусы, неизвестные события и повторы не увеличивают его.
- Поле development_summary добавлено в профиль и ответ выполнения. Старые сохранённые ответы complete без него поддерживаются; свежий профиль восстанавливает актуальное состояние.
- SVG-значки встроены в приложение. Добавленных зависимостей, новых таблиц/endpoint и обращений к OpenAI нет.
- Навыки, готовность и ранжирование не получают игровых бонусов.

## Автоматические проверки

- `npm run test:backend`: **57 passed**, 23.99 секунды; прежние 49 тестов и 8 новых проверок/параметризованных случаев.
- `npm run test:frontend`: **11 passed**. Пороги, отсутствие ложного прироста, старые идемпотентные ответы, валидация данных и отдельный mock-preview.
- `npm run build`: TypeScript и production-сборка успешны.
- `git diff --check`: ошибок нет.

Backend-проверки подтверждают подсчёт 0/1/2/3, исключения, импорт исторических завершений, идемпотентный replay, сохранение после повторного открытия БД, reset и неизменность расчётов/рекомендаций. Проверены права сотрудника на свой и чужой профиль.

Предупреждение Starlette TestClient о будущем переходе с httpx на httpx2 осталось от предыдущего этапа; на текущие результаты не влияет.

## Проверки интерфейса

На отдельной SQLite, с отключённым OpenAI:

1. Исходный сотрудник получил значки за существующую историю без поздравления при открытии.
2. Импортированный E9001 без истории начал с 0/2 earned.
3. Первое выполнение: First step, счётчик 1/3 и реальные изменения навыков/готовности.
4. Второе выполнение: 2/3 без второго значка; третье: Building momentum и 2/2 earned.
5. Reload и повторный выбор E9001 сохранили оба значка; role=status отсутствовал, новая анимация не запускалась.
6. При узком viewport 390 px карточки перенеслись в один столбец. Измеренные scrollWidth/clientWidth совпали (375 px), горизонтального переполнения страницы нет.
7. На fault-стенде GET профиля после успешного complete вернул 503. Значок сохранился по подтверждённому ответу complete; UI явно сообщил об успешном сохранении и ошибке обновления.
8. Refresh data устранил ошибку, сохранил 1/3 и не вернул класс анимации.

Консоль обычного тестового сценария: без ошибок и предупреждений. Поддержка prefers-reduced-motion реализована в CSS; переключение системной настройки движения в браузере отдельно не эмулировалось. Полного автоматического DOM/E2E-набора этот этап не добавляет.

Рабочая пользовательская БД не сбрасывалась и не использовалась для тестовых завершений. Локальные тестовые БД остаются в игнорируемой папке backend/var. После обновления запускать frontend и backend вместе, чтобы профиль содержал новое поле.
